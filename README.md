# ИС «Два Рояля» — конфигурация 1С:Предприятие 8.3

Информационная система управления записью и учётом занятий музыкальной студии «Два Рояля».

> **Статус: прототип/демо.** Конфигурация представлена в виде текстовой выгрузки метаданных
> (XML-дамп исходников). Продемонстрирована структура и бизнес-логика (учёт занятий,
> абонементов, аренды инструментов, контроль конфликтов расписания, СКД-отчёты, роли).
> Реального внедрения нет: дамп рассчитан на загрузку и проверку в платформе 1С 8.3.

- **Платформа:** 1С:Предприятие 8.3
- **Режим:** Управляемое приложение
- **Язык разработки:** русский

## Управляемые формы

Для каждого справочника и документа сгенерированы управляемые формы в виде XML
(`Forms/<Имя>/*.xml` + `Forms/<Имя>/Ext/Form.xml`):

- **ObjectForm** — карточка объекта (атрибуты + табличные части, напр. «Участники» у Занятия/Посещения);
- **ListForm** — список;
- **ChoiceForm** — форма выбора.

Для обработок сгенерирована форма `Form` (с командой «Выполнить»), для отчётов — формы
`Form` (основная) и `Настройки` (StandardSettingsForm).

> Формы сгенерированы в формате выгрузки XML. При первом открытии в Конфигураторе их
> стоит переоткрыть и сохранить (реформатировать) — платформа перезапишет файл в свой
> канонический вид; наличие форм здесь гарантирует, что конфигурация загрузится без
> автосоздания стандартных форм и с сохранёнными ссылками `DefaultObjectForm` и т.д.

## Ключевые объекты и бизнес-логика

### Справочники
- **Клиенты** — ФИО, дата рождения, телефон, e-mail, Telegram/TelegramID, комментарий, дата регистрации, статус, источник привлечения, ответственный менеджер, согласия на уведомления и обработку ПД.
- **Преподаватели** — специализация, дата начала работы, статус, ставка, филиал.
- **Направления** — длительность, базовая стоимость, тип (инд/групп), филиал.
- **Аудитории** — номер, вместимость, тип, филиал, оборудование, статус.
- **Абонементы** — количество занятий, срок, стоимость, направление, филиал, заморозка, переносы.
- **АбонементыКлиента** — учёт остатка: `Остаток = Количество − Использовано`; объектный модуль автоматически переводит статус (Истёк / Закончился).
- **Инструменты** — тип (рояль/фортепиано/гитара/…), филиал, инвентарный номер, статус, стоимость аренды в час.

### Документы и проведение
- **ПродажаАбонемента** при проведении создаёт абонемент клиента + регистрирует **Оплату**.
- **Оплата** пишет движения в регистр накопления «Оплаты».
- **ЗаписьНаЗанятие** проверяет наличие действующего абонемента с ненулевым остатком и добавляет клиента в участники занятия.
- **Посещение** проставляет статус занятия «Проведено», списывает занятие с абонемента (контролируя нулевой остаток), формирует движения посещаемости и загрузки.
- **ОтменаЗанятия** — статус «Отменено», возврат занятий на баланс по правилу.
- **ПереносЗанятия** — статус исходного «Перенесено», создание нового занятия, перенос участников, фиксация причины/исполнителя.
- **ЗаморозкаАбонемента** — ограничения: не истёкший абонемент, срок не превышает допустимый.
- **Возврат** — расход по оплатам, статус абонемента «Отменён».
- **АрендаИнструмента** — проверка доступности инструмента на период (по пересечению с существующими арендами), движения по регистру «АрендыИнструментов», автоматическая регистрация **Оплаты** и перевод инструмента в статус «Забронирован».

### Регистры
- **Информационные:** РасписаниеПреподавателей (периодический), ДоступностьАудиторий, НастройкиУведомлений, ИсторияИзменений.
- **Накопления:** ОстаткиАбонементов, Посещения, Оплаты, ЗагрузкаПреподавателей, ЗагрузкаАудиторий, АрендыИнструментов.

### Перечисления (16 шт.)
СтатусыКлиентов, СтатусыПреподавателей, ТипыЗанятий, СтатусыЗанятия, СтатусыПосещения, СтатусыЗаписи,
СтатусыАбонементаКлиента, ТипыАудиторий, ВидыОперацийОплат, ПричиныОтмены, ИсточникиПривлечения,
СтатусыПубликации, **Филиалы** (Ковалихинская / Коммуны — под реальные 2 площадки студии),
**ТипыИнструментов**, **СтатусыИнструмента**, **СтатусыАренды**.

### Контроль конфликтов (`CommonModules/КонтрольКонфликтовРасписания`)
Проверяет перед проведением занятия:
- занятость преподавателя;
- занятость аудитории;
- двойную запись клиента;
- выход за рабочее время.

Дополнительно для аренды: `ПроверитьДоступностьИнструмента()` — инструмент не в ремонте/не списан
и не пересекается с активными арендами на выбранный период.

### Аудит (`CommonModules/АудитДействий`)
Запись критичных операций (оплаты, продажа/заморозка/возврат абонементов, отмены, переносы, изменение расписания, архивирование клиентов) в регистр «ИсторияИзменений».

### Уведомления (`CommonModules/УведомленияСервер`, `DataProcessors/Уведомления`)
Отправка через внешние HTTP/API-сервисы (Telegram/e-mail/SMS): напоминания за 24 и 2 часа, отмены/переносы, окончание и низкий остаток абонементов.

### Роли (5 шт.)
| Роль | Доступ |
|------|--------|
| Администратор | полный |
| Руководитель | просмотр + операционные данные |
| Преподаватель | только свои занятия и ученики |
| Бухгалтер | финансы и финансовые отчёты |
| Наблюдатель | только просмотр |

### Отчёты (СКД, 8 шт.)
Расписание, Посещаемость, ЗагрузкаПреподавателей, ЗагрузкаАудиторий, Продажи, Клиенты, Абонементы, Задолженность.

## Загрузка конфигурации в 1С
1. Создать пустую информационную базу **1С:Предприятие 8.3**.
2. `Конфигуратор → Конфигурация → Загрузить конфигурацию из файлов…`
3. Указать каталог репозитория (корень, где лежит `Configuration.xml`).
4. `Конфигурация → Обновить конфигурацию базы данных` (F7).

## Соответствие критериям приёмки
Основные критерии (создание клиента/преподавателя/направления, расписание, контроль конфликтов, оформление абонемента, оплата, запись, отмена/перенос, посещение и списание, запрет использования законченного абонемента, отчёты, разграничение прав, журнал изменений, резервное копирование, импорт) реализованы в метаданных и модулях конфигурации.
